Git ve Github Temel Kavramları  

Repository: Kullanıcılar tarafından oluşturulan bir depodur. Bu depoda kullanıcılar projelerine ait dosyalarını, kodlarını ve yaptıkları değişiklikleri saklarlar. Projenin kim tarafından hangi değişikliklerin yapıldığını takip etmede bu depo önemlidir.

Bu görselde test amaçlı Github üzerinde bir repository oluşturulmuştur.  

Commit: Proje üzerinde yapılan değişikliklerin kaydedilmesine denir. Her commit sonucunda açıklayıcı bir mesaj eklenir. Bu sayede projede yapılan değişikliklerin takibi kolay olur.  
<img width="550" height="300" alt="image" src="https://github.com/user-attachments/assets/f3a103a9-e119-4580-b9b8-3562efd3cdfb" />  
Burada proje üzerinde yapılan değişiklik mesaj ile commit edilmiştir.

Push: Proje üzerinde yapılan değişiklikleri bilgisayardan depoya gönderme işlemine denir. Bu sayede Github üzerinde bilgisayarda yapılan değişiklikleri saklayabiliriz.  

Pull: Depoda bulunan güncel değişikliklerin bilgisayara aktarılmasına denir. Bu sayede ortak projeye yeni kod eklenmesi durumunda kullanıcı kendi bilgisayarına yapılan değişiklikleri çekebilir.  

<img width="550" height="300" alt="image" src="https://github.com/user-attachments/assets/5b606597-7e7f-407c-9e3a-390abefeebe8" />   

Burada yukarıda commit edilen yeniliğin push komutuyla githuba aktarılması ve pull komutunun nasıl yapılacağı gösterilmiştir. Ayrıca Git üzerinden de bu komutları denedim.

Branch: Ana kısımda yapılan projeyi etkilemeden güncellemeler yapmak ve değişiklikleri denemek için dallar oluşturulur. Bu dallara branch denir.

Stage: Değişikliklerin doğrudan kaydedilmeyip commit için hazırlanmasına denir. Yukarıda yapılan Hello World değişikliğini changes'dan stage durumuna aktararak commit edilmiştir.  

Merge: Farkli branch'lerde yapılan değişiklikleri birleştirerek main de toplanmasına merge denir. Branch'lerde yapılan güncellemeler pull komutuyla main'e alınır. Yukarıda test amaçlı oluşturduğum branch'i pull komutuyla main'de birleştirdim.  

Takımlar Neden Git ve GitHub kullanır?  

Birden fazla kişinin aynı proje üzerinde düzenli ve koordineli çalışması için takımlar Git ve GitHub kullanır. Otonom araç geliştiren takımlarda oldukça önemlidir çünkü bu platformlar sayesinde iş bölümü ve yapılan değişikliklerin takibi kolaylaşmaktadır.  

+ Versiyon kontrolüne neden ihtiyaç duyulur: Bir projede yapılan değişiklikleri takip etmek ve yapılan hataları görüp düzeltmek için versiyon kontrolüne ihtiyaç duyulur. Bu sistemin kullanılmadığı projelerde dosyaların karışması veya kaybolması, güncellemelerin kimin tarafından yapıldığının bilinmemesi, ekipçe çalışırken yazılan kodların birbirine geçmesi gibi sorunlarla karşılaşılabilir. Bu sistem kullanıldığında commit geçmişi ile bu sorunları çözebiliriz. Her commit bir mesajla yapılır ve yapılan değişikliği belirtir ve bu sayede bir hata oluştuğu zaman git komutlarıyla eski çalışan sürümlere dönerek hatadan kaçınalabiliriz.

+ Git ve GitHub arasındaki fark: Git, bilgisayar üzerinde yapılan değişiklikleri takip eden bir sistemdir. Git ile beraber komut kullanarak yapılan değişiklikleri kaydedebilir, kodları birleştirebilir ve branch'ler üzerinde ayrı ayrı çalışabiliriz. GitHub, yapılan projelerin internet üzerinde saklanması ve insanlarla bu projelerin paylaşılmasını sağlayan bir platformdur. Git bilgisayar üstünde çalışırken, GitHub internet üzerinden çalışır.

+ Ekip çalışmasına katkıları: Ortak bir projede çalışma yapılırken farklı branch'lerde projenin farklı özellikleri geliştirilebilir. Bu sayede iş bölümü daha kolaylaşır ve bir kişinin yazdığı kodu test edildikten sonra projeye aktarılır. Örnek olarak takımda bir kişi bir sensör üzerinden main branch'i değiştirmeden bir kod yazdı. Bu kodu main branch'le birleştirmek için önce Pull Request gönderilir. Code Review kısmında atılan bu kodun incelemesi yapılır ve eğer hata veya herhangi bir durum yoksa kabul edilir ve merge işlemi gerçekleştirilir. Merge conflict ise main ve branch'te aynı bölgede değişiklik yapıldığında Git hangi değişikliğin kalması gerektiğini karar verememesi durumudur.

+ GitHub proje yönetim özellikleri: Görev takibi için platformda Issues ve Projects gibi özellikler vardır. Projects kısmında takım devam eden ve tamamlanan görevlerin takibini yapmak için kullanır. Dökümantasyon için README ve WİKİ bulunur. Projenin amacı, teknik bilgileri ve detaylı açıklamalar bu kısımda bulunur. Otomasyon kısmında GitHub Actions sayesinde kod güncellemelerinden sonra otomatik test ve kontrol işlemi yapılabilir.

+ Kulüp ve takımlar için önemi: GitHub depo özelliği sayesinde geçmiş çalışmalar saklanır. Kodları, projeleri ve teknik dökümanları yeni gelen üyeler inceleyebilir ve kendi çalışmasını ona göre düzenler. Eski bilgi birikimi ve tecrübeler GitHub sayesinde yeni üyelere aktarılır.

+ Otonom araç projesindeki yeri: Takımda aynı araç için farklı birimlerin ortak çalışması bu platformlar sayesinde gerçekleşir. Örnek olarak takımda ayrı birimlerde görüntü işleme, karar verme ve davranış planlama, kontrol ve sensörler üzerinde her ekip ayrı ayrı çalışabilir. Kod değişikliklerinin takibi, kodların testi ve hata meydana geldiğinde geri dönülmesi için bu platformların kullanımı önemlidir.

+  Dikkat edilmesi gerekenler: Git ve GitHub yanlış kullanıldığında dosya kaybı, yanlışlıkla main branch'e kod gönderme ve kod çakışması gibi sorunlarla karşılaşabiliriz. Bu sorunları git komutları ile çözebiliriz. Örnek olarak yanlış branch üzerinde çalışmayı düzeltmek için git switch komutu kullanılabilir.
